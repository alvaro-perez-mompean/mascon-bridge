- **ボタン割り当て画面に「ゲーム」の選択欄を追加しました。** **JR EAST Train Simulator**
  を選ぶと、各ボタンの行にそのゲームでの機能名が並びます。ATS 確認、警笛、デッドマン装置
  リセットなど、マニュアルにある名前です。既定は **なし** で、そのときの表示はこれまでと
  まったく同じです。
- **`ZL` は「使用しないこと」と赤で表示します。** ゲームのマニュアルに赤字でそう明記されて
  いるボタンですが、これまでの画面は他と同じように割り当てられ、注意書きも出ませんでした。
  マニュアルに記載のない `Home` もその旨を表示します。ハットの行には四方向ぶん
  （逆転器・連絡ブザー・勾配起動）をまとめて出すので、あの行が四方向を担っていることが
  伝わります。表示されるのはゲームの**既定値**で、Steam のコントローラー設定で変更できます。
- **ハットは、倒すだけで割り当てられるようになりました。** これまではハットの行だけ、
  ハットではなく「その機器のどれかのボタン」を押す必要があり、倒しても何も起こりません
  でした。いちばん自然な操作が無反応だったわけです。今はどちらでも割り当てられます。
- **ブリッジ動作中に、割り当てが仮想マスコン自身を拾わなくなりました。** 仮想マスコンも
  Windows から見ればジョイスティックの 1 つで、しかも先頭に並びます。そのため割り当て済みの
  ボタンを押すと、手元の機器ではなく仮想マスコンが記録され、何も起きないか、ブリッジが自分の
  出力を読む割り当てができていました。動作中はその機器を候補から外します。

## 知っておくと良いこと

- 外すのはベンダー ID とプロダクト ID の一致で、**停止中は外しません**。本物の ZUIKI
  マスコンをお持ちの場合、ブリッジを止めていればこれまでどおり割り当てられます。動作中は
  ID が同一で区別できないため、本物も一緒に隠れます。
- `config.json` に `"Game"` が増えます（既定は `"none"`）。表示だけの設定で、ブリッジが
  送る内容は変わりません。

ノッチ値・HID レポート・軸の読み取りには手を入れていないので、運転の操作感は v0.2.3 と
同じです。

- **The button assignment page has a Game list.** Pick **JR EAST Train Simulator** and
  every row takes the name that button carries in the game — ATS confirmation, horn,
  deadman switch reset, and the rest, worded as the manual words them. It is set to
  **None** by default, and with None the page is exactly what it was.
- **`ZL` is shown in red as "do not use".** The game's manual prints it in red and says
  not to use it, and until now the page offered it like any other button, with no
  warning at all. `Home`, which the manual does not cover, says so rather than sitting
  blank. The hat row names all four of its directions — reverser, communication buzzer,
  hill start — so it is clear that one row carries four things. The names are the
  game's **defaults**; Steam's controller settings can move them.
- **The hat can be assigned by pushing the hat.** Only the hat row worked this way: it
  learns a whole device rather than one button, so it wanted you to press any button on
  the device instead, and pushing the hat did nothing at all. The most natural gesture
  was the one that did not work. Either way works now.
- **Assigning a button while the bridge runs no longer picks up the virtual mascon.**
  That mascon is one of the joysticks Windows exposes, and it is enumerated first, so
  pressing a button that was already mapped recorded the bridge instead of your
  hardware — a binding that either did nothing or fed the bridge its own output. It is
  now left out of the scan while the bridge runs.

## Worth knowing

- The exclusion matches on the vendor and product ids, and it **only applies while the
  bridge runs**. If you own a real ZUIKI mascon you can still bind it with the bridge
  stopped; while it runs the ids are identical and the two cannot be told apart, so the
  real one is hidden too.
- `config.json` gains a `"Game"` key, `"none"` by default. It is a display setting and
  changes nothing the bridge sends.

The notch values, the HID report and the axis reading are untouched, so it drives
exactly as v0.2.3 did.
